# Visão geral do projeto

## Propósito

Este repositório será desenvolvido de forma colaborativa por um grupo de participantes. Nesta etapa inicial, o foco é criar um processo organizado para transformar demandas em entregas versionadas, revisadas e integradas.

## Objetivos da fase de preparação

- manter as decisões importantes documentadas;
- praticar a abertura, execução e conclusão de issues;
- trabalhar com branches individuais e pull requests;
- revisar alterações antes da integração;
- realizar merges de forma rastreável na branch principal;
- estabelecer critérios claros para considerar uma tarefa concluída.

## Fora do escopo desta fase

- implementação de funcionalidades;
- definição prematura de linguagem, framework ou arquitetura;
- criação de banco de dados, APIs ou interfaces;
- configuração de uma pipeline de CI/CD antes de existir uma implementação a validar.

## Premissas de trabalho

- `main` representa a versão integrada e deve permanecer estável;
- cada alteração deve estar relacionada a uma issue;
- alterações de escopo devem ser discutidas e registradas antes da implementação;
- documentação e código, quando existirem, seguem o mesmo fluxo de revisão;
- o grupo deve preferir mudanças pequenas, fáceis de revisar e de integrar.

## Próximas decisões do grupo

As decisões abaixo devem ser registradas em issues próprias antes do início do desenvolvimento:

- problema de negócio e público-alvo;
- funcionalidades do primeiro incremento;
- stack tecnológica;
- arquitetura inicial;
- estratégia de testes;
- regras de proteção da branch `main` e revisores obrigatórios;
- convenção definitiva de commits, caso o grupo deseje uma mais específica.
